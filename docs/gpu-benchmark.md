# UYVY → NV12 硬件基准（第一阶段）

本文记录引入 staging 和执行槽复用前的实现；当前结果见 [流水线报告](gpu-pipeline-benchmark.md)。

测量日期：2026-10-03。RTX 5070 Ti 上的 30 帧全部匹配独立字节参考。
最终配置的单帧端到端中位耗时为 **2.731 ms**，P95 为 **2.853 ms**。

## 环境与输入

| 项目 | 实测配置 |
| --- | --- |
| CPU | Intel Core i7-13700KF；CPU 后端为当前串行参考实现 |
| GPU / 驱动 | NVIDIA GeForce RTX 5070 Ti / 595.91.07 |
| 系统 | Linux x86_64，内核 7.0.0-34-generic |
| 构建 | GCC 13.3，Release，`-O3 -DNDEBUG`，C++17 |
| Shader 工具链 | Clang/LLVM 18，glslang 15.1.0，SPIRV-Tools 2025.1；目标 Vulkan 1.1 |
| 输入 | 用户提供的 `30.zip`：30 个 1920×1536 UYVY 帧，stride 3840 |
| 每帧字节数 | 输入 5,898,240；NV12 输出 4,423,680 |
| 转换规则 | Y 保留；UV 相邻行 `(a+b+1)/2`；逐行扫描，输出垂直色度居中 |
| 最终 GPU 配置 | local size `32×1×1`，显式启用 `preferHostCached` |

性能测量关闭验证层。输入文件预先读入内存，预热全部 30 帧一轮，再循环十轮，
得到 300 个单帧样本。设备、内核、帧缓冲区和命令描述均复用。
所有单帧结果在计时后逐字节检查；驻留批次在最后一轮后逐帧检查。
CPU/GPU 基准依次运行，没有同时构建或运行另一份基准；未绑核、未锁频。
这是一台桌面主机上的测量，不是实时延迟保证。

## 最终结果

单位：ms/帧。P95 使用 nearest-rank；各阶段的中位数相加不等于整体中位数。

| 阶段 | CPU 中位数 | GPU 中位数 | GPU P95 |
| --- | ---: | ---: | ---: |
| 主机打包及上传 | 0.722 | 0.769 | 0.835 |
| 提交及等待 | 9.717 | 1.268 | 1.343 |
| 下载及主机解包 | 0.362 | 0.467 | 0.510 |
| 端到端 | 10.802 | **2.731** | **2.853** |
| GPU 设备命令区间 | — | 0.782 | 0.827 |

端到端覆盖上传、提交、等待、下载和本次提交资源销毁；排除磁盘 I/O、初始化、结果检查和
时间戳结果读取。它包含图像传输内部临时 vector 的分配，不代表零分配路径。
设备时间使用 TOP_OF_PIPE → BOTTOM_OF_PIPE 时间戳，包含 dispatch 和屏障，
不能当作纯算术指令耗时。关闭时间戳另测 90 个样本，中位数为 2.695 ms。

批量路径使用 **30 组独立输入/输出缓冲区**，一次提交，数据上传和最终下载在计时外。
十批共 300 帧，主机提交加等待合计 293.831 ms，折算 **1020.99 帧/秒**；
每批耗时除以帧数后，设备区间中位数为 0.955 ms/帧。
这个吞吐不包含主机图像传输，不能用来替代上表的端到端结果。
不同大小批次的摘要是“批次耗时折算每帧”的分布，整体吞吐使用总帧数除以总时间。

当前缓冲区仍为 host-visible storage buffer。在这台 GPU 上，缓存配置选择了
HOST_VISIBLE | HOST_COHERENT | HOST_CACHED 的系统内存类型（type 3，heap 1）。
“驻留”表示复用 GPU 可访问的资源，没有声明数据位于独立显存。
30 组设备帧共 309,657,600 字节，约 295.3 MiB，另有主机输入及临时存储。

## 改动依据

以下探索配置各测 90 个单帧样本，最终配置见上表的 300 样本复测。

| 配置 | 端到端中位数 | 设备区间中位数 |
| --- | ---: | ---: |
| 原始逐字节打包，X=1，默认 coherent 偏好 | 20.751 | 2.471 |
| 仅改为小端主机逐行 memcpy | 10.269 | 2.488 |
| 再改 X=32 | 9.111 | 0.714 |
| 改为 X=64 的对照 | 9.335 | 0.789 |
| 改为 X=128 的对照 | 8.811 | 0.749 |
| X=1、优先主机缓存内存的试验 | 53.479 | 46.933 |
| X=32、优先主机缓存内存的试验 | 2.989 | 0.802 |

保留逐行复制及可配置工作组，图像算子默认 X=32：本次设备区间更短，且 1920 宽输入的
480 个工作项可以整除 32。64/128 需补齐到 512；其端到端排序也受下载波动影响。
工作组大小通过 `LUTILS_IMAGE_LOCAL_SIZE_X` 调整，不视为跨硬件最优值。

缓存策略与工作组存在明显交互：X=1 时退步，X=32 时改善端到端、但驻留计算略慢。
因此它是 `VulkanOptions::preferHostCached` 显式选项，默认关闭，不修改普通设备工厂的策略。
该观察不足以确定所有微架构原因，后续需要设备 profiler 才能进一步解释。
640×480 合成小图另测 30 次：逐行复制、X=1 的中位数 1.964 ms，最终配置 0.560 ms。

## 验证与复现

硬件集成测试覆盖空图、奇高、负 stride、padding、工作组尾部、元数据与 SPIR-V 不匹配、
不可整除 dispatch，以及大 invocation 索引的乘法回绕保护。
最终 30 帧测试另启用 Khronos 验证层 1.3.275 和同步验证，以 29+1 尾批执行，
在所有资源销毁后汇总为 **0 errors / 0 warnings**。
Release 测试 25/25 通过；Clang ASan/UBSan/LeakSanitizer 测试 25/25 通过；
关闭可选计算依赖的默认构建测试 11/11 通过。泄漏检查在宿主环境完成，以避开沙箱 ptrace 限制。

构建和通用命令见 [README 的硬件验证与性能基准](../README.md#硬件验证与性能基准)。

```sh
./build/compute-release/benchmarks/uyvy_nv12_benchmark vulkan 1920 1536 gpu-repeat.json \
  --require-hardware --timestamps --host-cached --rounds 10 build/uyvy-30/input/{1..30}.uyvy
```
