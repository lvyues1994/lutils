# 类型擦除模块

## 调用机制

同一个接口模板分别应用于抽象模型、具体值模型、引用模型和拥有对象代理。业务方法由编译器生成的虚表分发：

```text
owner.method()
  → 接口模板在代理层的方法
  → value(*this) 返回抽象接口引用
  → 虚调用进入具体模型的同名方法
  → value(*this) 返回 T& 或 T const&
  → 调用具体对象

pointer->method()
  → 视图缓冲区中的引用模型
  → 虚调用进入具体模型的同名方法
  → 调用借用的具体对象
```

接口方法体需要分别对具体对象和抽象接口成立；直接成员转发通常保持同名。自由函数适配还需要为抽象接口提供转发入口，例如测试中的 ADL 隐藏友元。`const` 方法会取得 `T const&`；引用返回值和重载按 C++ 规则保留。抽象层的 `value()` 保留调用处的静态接口类型，使转发体在 C++17 下可以实例化；若抽象占位实现意外执行，则终止进程。

该机制参考 [ericniebler/any](https://github.com/ericniebler/any/tree/6d75dd31b0468d823fb3da8485f94793fe7e20b1)。本实现针对 C++17 编写，未引入上游的 C++23 constexpr、反射辅助或动态查询设施。

## 模块边界

路径均相对于 `erasure/include/lutils/erasure/`。

| 模块 | 文件 | 职责与内部契约 |
| --- | --- | --- |
| Interface | `Interface.hpp` | 声明、组合和线性展开接口；提供 `value()` 和借用绑定槽 |
| Model | `detail/Model.hpp` | 将接口应用到持有 `T` 或 `T*` 的根模型；区分可写和只读目标 |
| Storage | `Storage.hpp` | 管理堆／内联模型的构造、销毁、复制和转移；替换使用候选对象提交 |
| Lifetime | `Lifetime.hpp` | 声明复制／移动能力，用控制基类启用或删除特殊成员函数 |
| Owner | `Any.hpp` | 暴露 `Any`、原位构造、空状态及管理函数；构造时检查目标生命周期能力 |
| Borrow | `AnyPtr.hpp`、`detail/BorrowStorage.hpp` | 在视图内部构造适配器；复制借用关系和向基接口投影 |

这些模块共同组成一个头文件库目标 `lutils::erasure`。业务虚函数通过原生虚表调用；内部操作表仅管理模型的存储和生命周期。

## 接口组合

`Extends` 按声明顺序进行后序遍历，以接口模板身份去重。例如 `Derived` 扩展 `Left`、`Right`，两者都扩展 `Base`，最终继承链为：

```text
Derived<Right<Left<Base<Root>>>>
```

重复接口只出现一次，循环扩展会产生编译错误。方法覆盖、同名隐藏和重载使用普通 C++ 规则；库不分析方法签名，也不自动合并同名重载集。

接口模板必须无状态，使用继承构造函数，并由编译器生成特殊成员函数。普通虚成员可带 `const`、`&`、`const &`、`noexcept`；需要转发参数时由接口体显式调用 `std::forward` 或 `std::move`。

## 拥有对象与存储

| 接口能力 | Any 复制 | Any 移动 | 目标要求 |
| --- | --- | --- | --- |
| 无 | 禁止 | 禁止 | 可以原位构造，可包含不可复制、不可移动的目标 |
| `IMovable` | 禁止 | `noexcept` | 移动可以只转移堆指针，目标自身不必可移动 |
| `ICopyable` | 按目标复制构造 | `noexcept` | 目标必须可复制构造；其内部资源如何复制由目标类型决定 |

这些限制作用于真实的特殊成员函数，`std::is_copy_constructible` 等生命周期 traits 可据此判断。它们不检测任意接口方法体是否有效：目标缺少某个业务方法时，可能直到实际构造模型才报错。

默认 `HeapStorage` 在堆上构造完整模型。`SmallBufferStorage<Bytes, Alignment>` 只有在**完整模型**的大小、对齐满足缓冲区要求，且从目标右值构造模型不会抛出时，才使用内联存储；否则回退到堆。完整模型包含多态开销，不能只用 `sizeof(T)` 估算。默认 SBO 参数是三个指针的容量和 `alignof(std::max_align_t)` 的对齐。

目标析构必须不抛出异常。复制赋值和 `emplace` 先构造候选模型，成功后再以不抛出的操作提交；若构造失败，旧模型保持有效。在参数及目标复制构造不修改旧对象的前提下，其值也保持不变。模型内部存储可以转移，所以这一提交过程也支持公开 API 不可移动的 `Any`。

移动成功后源 owner 为空；自复制、自移动、自交换保持原值。`swap` 只为可移动 owner 提供。默认构造得到空对象；调用空对象的业务方法属于契约违反，会调用 `std::terminate`。业务异常正常传播；接口成员若声明 `noexcept`，其目标抛出时同样终止。库不会自动证明目标调用符合 `noexcept`，严格检查需要接口作者自己添加 `static_assert`。

## 借用与生命周期

`AnyPtr<I>` 可空、可复制；const 视图对象仍可修改所指目标。`AnyConstPtr<I>` 只暴露 const 接口成员，可从 mutable 视图显式构造，反向转换禁止。借用能力不要求目标可复制，即使接口包含 `ICopyable`，不可复制目标也可以被借用。

适配器保存在视图自己的对齐缓冲区中，使用 placement new 和匹配的具体析构函数管理寿命。复制视图会重新构造适配器，底层 `T` 不被复制、移动或销毁；借用管理不分配堆内存。

向基接口投影时，原模型通过虚绑定槽向新视图写入最终目标地址。因此目标视图不依赖源视图的适配器，源视图销毁或 reset 后仍可使用。对 const 目标，适配器只保存 const 指针，不使用 `const_cast`。

用户负责保证目标存活。以下操作使相关借用失效：目标销毁，以及被借用 owner 的 reset、成功替换、非自移动或非自交换。即使某个堆存储场景下地址恰好不变，也不应依赖这种行为。复制 owner 不影响指向原 owner 目标的借用；失败的替换不会销毁旧目标。借用视图自身的移动会清空源视图，reset 只解除自身的借用关系。

## 当前边界与验证

当前不提供拥有对象间的跨接口转换、运行期接口查询、具体类型取回、消费型 `&&` 接口、完整 constexpr 擦除对象或跨 DSO 的 ABI 承诺。接口模板不能为擦除后的成员模板建立虚调用。

测试包含普通调用和引用返回、自由函数适配、复制移动 traits、菱形去重、视图生命周期、异常安全、SBO 回退与对齐、分配计数、跨翻译单元传递，以及编译失败和契约终止检查。实现中的默认 `Link` 参数属于内部细节，用于让 GCC 13 正确保留匿名接口的内部链接属性，避免编译器崩溃或合并不同翻译单元的虚表；用户应保留其默认值。跨翻译单元测试保留了两个同名匿名接口作为回归覆盖。
